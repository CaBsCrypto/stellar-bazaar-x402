# Environment Variables · Stellar Bazaar x402

> Nota en español: esta guía técnica está en inglés. Para la descripción general del proyecto en español, consulta [README.es.md](../README.es.md).

Every environment variable the app and test scripts read, where it comes from,
and how to treat it locally vs in production. Sources: `.env.example`,
`lib/x402-config.ts`, `lib/dynamic-registry.ts`, `lib/external-provider.ts`,
and the scripts listed below.

## Loading behavior

- **`.env.local`** — auto-loaded by Next.js. Holds all server-side envs for
  `npm run dev`.
- **`.env.x402.local`** — generated by `npm run x402:setup-wallets`
  (`scripts/setup-testnet-wallets.mjs`). **Not** auto-loaded by Next.js.
  Read explicitly by `scripts/test-x402-client.mjs`,
  `scripts/diagnose-x402-server.mjs`, and (as fallback) by
  `scripts/test-agent-autonomous-flow.mjs` / `examples/agent-autonomous-buyer.mjs`.
  Merge its values into `.env.local`.

## Test scripts that read env

- `scripts/test-e2e-ecosystem.mjs:4` — `BASE_URL`.
- `scripts/test-mcp-onboarding.mjs:3,10` — `MCP_BASE_URL`, `BAZAAR_PROVIDER_SECRET`.
- `scripts/test-publisher-ingest.mjs:3,8` — `BASE_URL`, `BAZAAR_PROVIDER_SECRET`.
- `scripts/test-x402-protocol.mjs:4` — `X402_RESOURCE_BASE_URL` then `BASE_URL`.
- `scripts/e2e-external-provider-testnet.mjs:1-3` — `RUN_EXTERNAL_X402_TESTNET=1`,
  plus `EXTERNAL_QUOTE_BASE_URL` (must be HTTPS), `X402_PAYER_SECRET`,
  `STELLAR_X402_FACILITATOR_API_KEY`.
- `examples/agent-autonomous-buyer.mjs:15-26` — loads `.env.local` (or
  `.env.x402.local`), then `BASE_URL`, `X402_PAYER_SECRET`.

## Security notes

- Never deploy `X402_PAYER_SECRET` or `X402_SELLER_SECRET`; they are
  TESTNET-ONLY hot wallets (file headers in `.env.example` /
  `.env.x402.local`).
- Generate `BAZAAR_PROVIDER_SECRET` with `openssl rand -hex 32` and keep it
  out of git (`.env*` is gitignored, `.env.example` excepted).
- Registry persistence via `UPSTASH_REDIS_REST_URL`/`TOKEN` is **LIVE since
  2026-08-19** (free tier, provisioned via Upstash console). Without them the
  registry falls back to an in-memory `Map` (`lib/dynamic-registry.ts:22-34`),
  so registered cards do not survive a redeploy. `storageMode()` reports
  `"memory"` vs `"upstash"`; verify `"upstash"` in register responses.

## Demo-pay wiring (local only)

`POST /api/x402/demo-pay` works only when **all three** are in place
(`app/api/x402/demo-pay/route.ts:12-23`):

1. `X402_ENABLE_LOCAL_PAYER=true` (else `403 LOCAL_PAYER_DISABLED`);
2. `X402_PAYER_SECRET` set (else `503 PAYER_SECRET_MISSING`);
3. `X402_RESOURCE_BASE_URL` loopback — `http://127.0.0.1:3000` when the app
   runs on 3000 (else `400 LOCAL_PAYER_TARGET_REJECTED`, because
   `requireLocalResourceBaseUrl()` rejects non-loopback origins,
   `lib/x402-config.ts:12-17`).
