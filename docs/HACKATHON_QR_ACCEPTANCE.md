## Cierre público pendiente

Presentar candidato, configuración y evidencias para autorización separada de producción. Sólo tras publicar la versión aprobada se acepta desde un cliente externo sin acceso de operador: QR → cuenta nueva → MCP → catálogo → orden → compra autorizada → entrega → historial privado. Registrar evidencia del recorrido completo, recuperación y rechazo de otra cuenta. El QR público no está aceptado por las seis comprobaciones de preview.

La compra anterior y su continuación ya consumieron sus permisos; cualquier nueva transacción necesita servicio, cantidad e importe Testnet autorizados por separado. El alcance de cierre es texto. Imagen/video y entregas R2 pagadas permanecen pendientes. El [vendedor continuo](HACKATHON_CONTINUOUS_SELLER.md) se prepara en el proyecto externo del proveedor con Redis durable cifrado y locks atómicos: tick cada cinco minutos, máximo una orden por tick, 50 ejecuciones/día y 5.000 solicitudes MCP/día del worker. Sigue en standby hasta validación y autorización de producción. Su conexión con Bazaar usa únicamente MCP y el acceso propio de vendedor; Bazaar no ejecuta código arbitrario de proveedores. Las pruebas de preview serán ticks manuales sin cron programado ni pagos nuevos. La ejecución aceptada anteriormente fue una invocación acotada. El [detalle de la compra](HACKATHON_NEXT_PURCHASE.md) separa el fallo previo de preparación, la continuación autorizada y el resultado confirmado. No iniciar otro pago o ejecución para recuperar un resultado existente.

El nuevo core, handler, store y proveedor Express pasaron **61, 28, 13 y 8 comprobaciones offline**, respectivamente; el core incluye diagnóstico de transporte y el paquete desplegable del proveedor pasó 40. También pasaron las regresiones del kit externo (47), supervisor (34), guionista (18) y ambos builds locales. El SDK real con transporte sintético midió cinco HTTP MCP por tick ocioso y 31 llamadas Redis REST por tick caliente, 32 iniciales, mediante un doble de comandos AES/CAS. A cinco minutos se proyectan 1.440 HTTP MCP/día y 267.840 Redis REST/30 días antes de ejecuciones y otros usuarios. No es consumo facturado ni telemetría alojada. Una orden puede esperar unos cinco minutos más ejecución o backlog; consultar no repite el pago.
