# Open operations policy

This policy applies to the prospective open release on `https://bazaar.browns.studio`. Historical acceptance receipts and the protected acceptance preview remain evidence of their original bounded run. This source change does not deploy, publish, alias a domain, modify Carmelita, provision another service, invoke a provider, or execute the separately authorized future test payments.

## Exposure and authorization

Set `BAZAAR_ROUTE_BOUNDARY=true` independently of `BAZAAR_WORKSPACE_ADMISSION=open`. Open admission has no invite hashes. The boundary exposes the explicit marketplace, workspace, history, MCP, documentation and skill routes in `lib/pilot-route-policy.ts`. Native payment/demo, legacy publisher and `/api/admin/*` paths remain closed. Marketplace review, control and operations-budget routes verify the existing private operator credential inside their native handler. A matching bearer format is only an early rejection check; it never grants a role.

The public catalog and discovery routes allow anonymous reads. Submission details, orders and permission controls retain native owner/role authorization. A human controls delegated market permissions. The SDK MCP endpoint keeps credentials in the request header and each tool's native handler verifies its own role. Actual HTTP x402 USDC Stellar Testnet execution remains in the compatible local buyer; MCP does not hold or sign wallet secrets.

The proxy rejects an unknown route/method, malformed supplied bearer, disallowed origin or query, unsupported content type, dishonest/oversized Content-Length, invalid JSON, and bodies beyond the route's byte limit before auth Redis. Its bounded cloned read preserves the native handler's body. Next.js static assets and image/font/icon files bypass the function matcher. The proxy is an exposure boundary; handlers retain authoritative authentication and validation.

The Vercel project WAF must supply a global pre-function limit for anonymous discovery/MCP and the private operator paths before exposing continuous traffic. The source does not assert that an existing WAF rule is configured. The local operator controller backstop allows twenty authorized requests per minute per process; invalid credentials reach no Redis. This process-local guard is insufficient to establish a global Vercel limit.

## Metering

Set `BAZAAR_OPERATIONAL_METER=true` with acceptance switches false. Existing API wrappers, nested MCP/native handlers and SSR readers share the AsyncLocalStorage transport hooks. Counters include anonymous API requests, invalid-token handler responses, SSR reads and thrown/error outcomes. A proxy rejection counts as one request; a continuing proxy event counts zero requests so the later API request is not counted twice. Nested measured handlers reserve one budget and use the same counters. No token, key, raw argument, signed transaction, provider response or record content is logged.

Responses expose `X-Bazaar-Operational-Meter: v1`, a random operational request ID, Redis REST exchanges, Redis command upper bounds, Redis payload bytes, each bounded external transport kind, external body bytes and an uncertainty flag. `recordOperationalStorageBounds({market:{committedBytes,reservedBytes}})` lets the shared-capacity projection report effective stored-byte upper bounds before EVAL. These observations include committed documents and paid-completion reservations and carry `X-Bazaar-Storage-Observation: prospective-upper-bound`; they do not assert the projected CAS succeeded. Loop-free EVAL command bounds include EVAL plus every possible `redis.call`. A root capacity CAS with three store GETs, two guard GETs and three SETs costs at most nine Redis commands in one REST exchange. Loops and unrelated key namespaces are rejected. Errors with an unknown transport acknowledgment are counted and marked uncertain.

Transport limits and reservations now follow reachable request work:

| Work | Redis REST / commands | Redis outbound / inbound | External calls / outbound / inbound | DTO allowance |
| --- | --- | --- | --- | --- |
| Public catalog/discovery/SSR | 7 / 12 | 192 KiB / 6 MiB | 0 / 0 / 0 | 128 KiB |
| Static MCP metadata/capabilities/skills | 2 / 4 | 192 KiB / 64 KiB | 0 / 0 / 0 | 128 KiB |
| New authenticated work/payment | 34 / 330 | 9 MiB / 17 MiB | 3 / 256 KiB / 512 KiB | 128 KiB |
| Verified existing recovery/finalization | 34 / 330 | 9 MiB / 17 MiB | 8 / 256 KiB / 1 MiB | 128 KiB |

The public catalog reads market state, review snapshot and workspace registry once each: two GETs plus the three-GET workspace EVAL cost six business commands in three exchanges. Discovery/SSR can additionally read the catalog index and cards, adding two commands/exchanges. Budget GET and CAS add two exchanges and four commands, giving the public maximum seven/twelve. Its 6 MiB inbound allowance covers JSON-escaped replies for 512 KiB market, 1 MiB review and 1 MiB registry documents, the bounded duplicate catalog-card view and ledger/transport framing. Metadata has no business Redis effects and reserves only the budget GET/CAS. Public requests cannot invoke an external transport.

Authenticated/recovery Redis bounds include quota conflict retries, full multi-key capacity CAS arguments and recovery writes; those larger bounds remain intentionally conservative. A fresh x402 payment can reach two facilitator calls and one RPC call. Each existing x402 transport bounds request bodies to 64 KiB and response bodies/headers to 128 KiB; the new envelope includes request headers and these three responses. Recovery allows bounded RPC and proof transports and rejects facilitator calls, so a read cannot settle a payment. Operational guards use these same profile limits. Redis byte counters are measured after the SDK returns a reply; an oversized final reply can cross an aggregate allowance before the guard returns an error. Such a request is marked uncertain. This is not a hard upstream bandwidth or billing wall.

These are technical work/byte guards, not counts of buyers, sellers, services, cards or orders. Stored-byte fields describe prospective guarded observations; zero means no observation, not an empty database. Storage pressure reports an alert at 70% of effective serialized bytes plus completion reservations, using 12 MiB workspace, 512 KiB market, 1 MiB review, 128 KiB settlement and 64 KiB ledger caps. Catalog storage has no fabricated aggregate cap. This meter does not measure platform CPU, CDN traffic, live credit, wire overhead or the full billing account.

## Budget ledger and refresh

Set `BAZAAR_OPERATIONAL_BUDGET=true` only with the operational meter enabled and a verified `BAZAAR_OPERATIONAL_CHECKPOINT_JSON`. The checkpoint contains version 1, a fresh UUID epoch, UTC observed/expiry timestamps, a redacted evidence identifier and current remaining operational quantities: requests, Redis REST exchanges, Redis commands, combined payload bytes outbound/inbound, and external invocations. The operator can choose a weekly or billing-cycle epoch, at most 31 days and no later than the actual quota reset. There is no daily forced closure. A stale checkpoint still pauses new work, so continuous operation requires a finite renewed quota epoch rather than an unverified perpetual balance. Shared consumption and delayed usage require the retained unassigned reserve and earlier operator refresh when conditions change. Infrastructure quantities need current management-plane evidence and explicitly authorized external-call allowances. A historical snapshot, variable presence or unknown value is never substituted with a fabricated zero/current balance.

Of each supplied remaining quantity, 50% remains unassigned. The other half is allocated deterministically: public reads 20%, authenticated new work 50%, existing reads/recovery/finalization 30%. Integer rounding increases the unassigned reserve. The ledger reserves the appropriate profile envelope above, combining Redis/external payloads and the 128 KiB DTO allowance, including the GET/EVAL admission itself. Static metadata uses its smaller envelope in the same public allocation. A public profile's zero external allowance is inapplicable to its pressure calculation and never consumes facilitator quota. Reservations remain held on lost acknowledgment; actual meter observations are available separately. Infrastructure request allowance must come from bounded function/proxy CPU, memory, duration and artifact/deployment costs against current team credit; an arbitrary HTTP count does not establish a cost budget.

Each profile reports an alert at 70% of its allocation. Admission that would take new work above 75% of any assigned quantity returns `NEW_OPERATIONS_PAUSED` with Retry-After. Public reads and existing history, revocation, recovery, claim and paid finalization retain their separate allocation until its 100% technical exhaustion. This rule pauses new application operations only; it does not pause the Vercel team, alter billing settings, or claim an absolute zero-dollar spending wall. Existing minute/day workspace quotas remain an additional authenticated request backstop.

The outer `/api/mcp` request is classified from only the bounded method/tool name. Public discovery, including `list_market_services`, uses public; static capabilities/skills use metadata; create/submit uses authenticated; private history/finalization defers recovery reservation until authoritative credential and requested-role verification. `creditOperationalPrincipal()` is called from verified workspace/history/operator authentication. Before verification, transport uses the public bound; a fake bearer consumes only public, and public exhaustion cannot block a valid caller's bounded credential read or retained recovery allocation. Native nested handlers reserve once. Provider-status token checks must call the same credit hook only after token verification. Unverified errors are metered and conservatively charged to public when the ledger permits it; global WAF remains necessary to bound rejected/unauthorized traffic and admission overhead.

Every `/api/market/orders/{id}/x402` request uses deferred verified recovery for its existing intent. The x402 handler calls `operationalRequestGate({profile:'authenticated',newOperation:true})` immediately before a fresh challenge or signed verification is reserved; this upgrades its transport profile before facilitator effects. Paid or uncertain persisted attempts recover without another new-work gate. A fresh payment can reserve two conservative envelopes intentionally; the HTTP request meter still records one outer request. Recovery cannot start another payment or provider execution.

The ledger resides only at the existing workspace prefix plus `:operations-budget:state`, has no TTL and is capped at 64 KiB. Its loop-free single-key compare-and-set makes concurrent admission atomic. A definite CAS conflict or unknown acknowledgment is never replayed. Unknown acknowledgments retain the reservation if the SET committed. Incomplete config or malformed state fails closed. A stale checkpoint blocks new work while reserved recovery/public reads can continue.

The private operator uses GET `/api/market/operations-budget` to inspect allocation, usage, pressure and checkpoint freshness. POST supplies a newer, unexpired checkpoint with a different epoch and the same schema; it can restore admission only after the operator has refreshed actual quota/billing evidence. These inspection/refresh calls remain available when request allocations are exhausted and have a separately bounded operational/WAF allowance. They are metered but do not reserve the exhausted application ledger. This operator refresh is periodic external evidence collection, not an automatic vendor billing monitor. Any other projects sharing the Redis database or Vercel team can consume quota between checkpoints.

## Storage and activation evidence

Retain document byte guards: 1 MiB registry, 12 MiB workspace documents, 128 KiB per owner, 512 KiB market state, 128 KiB settlement state, and the additional 64 KiB budget ledger. The root shared-capacity implementation independently reserves paid completion space; policy removes commercial count caps without removing these technical byte bounds. A pressure response must use actual serialized prospective state bytes and reserved completion bytes.

The bounded [current preflight](validation/open-operations-preflight.md) confirms the project, verified domains, protection setting and Node 24/Next.js configuration. The parent's October 7 dashboards confirm existing Free Tier Redis with conservative remaining snapshot bounds of 495,800 commands, 9,991,611,392 bandwidth bytes and 255,946,752 storage bytes, and Vercel displayed included credit usage of $18.72/$20.00. The conservatively rounded credit remaining lower bound is $1.27; half is $0.635 before deployment/artifact and shared-consumption allowances. Vercel says usage can lag by one hour, so this is a delayed shared snapshot, not a permanent spending guarantee. Dedicated workspace Redis variable names were absent from production metadata while present in preview; the existing URL must match the observed hostname. The source manifest leaves the production mapping and bounded compute/request derivation unresolved and carries no live checkpoint. Activation requires current mapping, a complete checkpoint and confirmed WAF rules. Historical receipts are unchanged.
