# Anonymous Vercel toolbar sizing: executed observations and future safeguards

The existing `docs/evidence/sprint-marketplace/usdc-toolbar-assets.json` belongs to plan `7f3e80be-d9be-47e1-81c8-49445b3bc0d9`, application SHA `a741937b6d389edbd333ff51bac95b68e654d40e`. It records exactly two anonymous GETs: the fixed `vercel.live` feedback JavaScript and HTML bootstrap resources. Both returned HTTP 200 with fully consumed responses. The report contains 204,763 inbound bytes, zero request payload bytes, 394 ms of active execution and no uncertain attempt.

The executed script version **did not acquire the shared sale-effect lock or check the current aggregate budget and frozen reserves before each GET**. The coordinating process reports that this was one known controlled probe process. That observation does not establish retrospective exclusion of every concurrent process. The executed receipt remains unchanged; the new safeguards do not certify an earlier guarantee that the earlier executor lacked.

These resource sizes cover the two bootstrap responses only. They do not prove absence or cost of earlier browser downloads, redirects, feedback API calls, transport retransmissions or other platform traffic. The report's limitation remains applicable. This sizing probe does not approve the marketplace opening, native 200% zoom or human Freighter signing.

`scripts/check-usdc-toolbar-assets.mjs` is now import-safe and acquires the existing shared `sale-<planId>.lock` before reading effect receipts or issuing a request. It imports the packet directory but never loads or decrypts the packet. An existing sizing receipt prevents all requests and is never overwritten. An existing uncertain receipt keeps the lock; no automatic recovery or retry is attempted.

Before **each** GET, the future executor reloads the nine known hosted effect reports, any published browser transport receipt and known server meter exports. It rejects uncertain evidence, validates plan/SHA bindings and counts additional server records once by deployment and request UUID. Driver API records already counted by the driver are excluded from extra server costs. Known browser transport bytes and time are added separately from the server's Redis/external costs. The full frozen browser reserve remains additional to observations; incomplete browser capture cannot reduce it.

The gate reserves one prospective response up to 1 MiB plus 32 KiB of response headers, its 12-second deadline and the frozen browser API/byte/time reserves. A first execution requires explicit browser payload/time reserves in the manifest, or the exact browser budget receipt fixed by SHA-256. An absent byte/time reserve does not become zero. The receipt binding also checks the replacement deployment ID, source SHA and origin. Manifest, driver and previously executed evidence were not changed by this hardening.

The executor saves the request intent before transport. Response headers, every consumed body chunk and elapsed time remain recorded when a response fails partway. A lost response, oversized response or receipt-write uncertainty preserves the shared lock and stops further GETs. A fully received non-200 result is a known rejection with no second request. Local tests cover these cases, exhaustion of each aggregate limit, a budget change between requests, duplicate server observations, budget-hash substitution and immutable existing receipts. They use injected storage, locks and transports: zero network requests, DPAPI operations or wallet effects.
